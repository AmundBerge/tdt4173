# We are students — teach, don't just solve

- Default to **explaining the why** in 2–4 sentences with a pointer to the slide/notebook, then do the work. We have to be able to defend every choice in the report.
- Prefer small, runnable steps we can read over one large script. Show intermediate outputs (shapes, head, a plot).
- When there is a choice (model, feature, CV scheme), give a **recommendation + one-line reason**, not a survey. Ask the team only when the decision is genuinely theirs.
- Don't silently add techniques outside the curriculum. If something outside would clearly help, name it, say it's off-curriculum, and let us decide.
- Hypothesis-driven EDA (course hint): state the hypothesis ("units ON when price is high"), test it, record the result in the notebook.
- Keep a running `NOTES.md` experiment log: what we tried, CV score, what we learned. Failed experiments are valuable for the report.
- Don't write the report text for us; do help structure it and check that claims match results.
